## Naming note (no change requested)

The user brief for this wave said "app" and "app-data". DEVOPS keeps the DESIGN names: the service is `planner`, the volumes are `planner-data` and `valhalla-data`. The compose project `overland` gives the Docker names `overland_planner-data` and `overland_valhalla-data`, fixed with an explicit `name:` so the ADR-018 backup commands stay stable.

## Not contradicted (checked)

- D52 "Valhalla port not published": kept. The live contract run uses an ephemeral `valhalla-tunnel` forwarder bound to 127.0.0.1 only for the run (D95). Valhalla itself is never published, so 127.0.0.1 publishing was not needed.
- D53 resource caps: kept (planner 1g, Valhalla 4g, build 9g with serving stopped). DEVOPS adds `cpus`, `memswap_limit` and `oom_score_adj` (D83).
- Brief §12 "planner depends on valhalla (service_started only)": kept.
- ADR-018 backup/restore procedure: **not adopted as an operated routine.** The user does not want backups (2026-11-02, D91). Only the ADR-018 pre-migration copy and the D89 predeploy snapshot remain, for rollback. Accepted risk: device/NVMe loss = data loss. The README should state this instead of the ADR-018 backup steps.
